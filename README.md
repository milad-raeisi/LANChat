# LANChat

**Secure, terminal-native instant messaging for your local network.**
Simple to install. Easy to use. Secure by default. No internet, no accounts, no cloud.

LANChat runs entirely in your terminal. Start it, enter your name, pair with the
people around you, and chat — over the LAN, peer to peer, encrypted with TLS 1.3.

## Install with one command

**macOS and Linux**

```sh
curl -fsSL https://raw.githubusercontent.com/milad-raeisi/LANChat/main/scripts/install.sh | sh
```

**Windows (PowerShell)**

```powershell
irm https://raw.githubusercontent.com/milad-raeisi/LANChat/main/scripts/install.ps1 | iex
```

The installer downloads the latest GitHub release for your OS and CPU, **verifies its SHA-256
checksum**, installs `lanchat` for the current user (no administrator rights) and makes sure it is
on your `PATH`. It never changes firewall or network settings. If no release has been published
yet, it builds from source with `go install` when Go is available.
Options and other methods (Go, release archives, `.deb`/`.rpm`) are in
[docs/installation.md](docs/installation.md).

## Quick start

```sh
lanchat
```

1. The first launch opens a setup wizard: enter your display name (the device name is pre-filled),
   keep **Automatic network discovery**, and let it check your setup.
2. Other LANChat users on your network appear under **NEARBY – NOT PAIRED**.
3. Select a person (`Tab` to the sidebar, `↑↓`, `Enter`) or type `/pair maryam`. Both of you see the
   same **six-digit verification code** — compare it out loud, then accept.
4. Chat in `# general`, open a private conversation with `/msg maryam Hi!`, send a file with
   `/file send maryam ./report.pdf`.

Run `lanchat doctor` if peers do not show up.

## Features

- **Automatic discovery** with mDNS/DNS-SD (`_lanchat._tcp.local.`) on suitable LAN interfaces;
  static peers and an optional [managed discovery server](docs/managed-discovery.md) for
  segmented networks and VLANs.
- **Decentralized, peer-to-peer** messaging over TCP. Every instance is client and server; there is
  no central message server.
- **TLS 1.3 with mutual authentication** for every connection. Each installation has a persistent
  Ed25519 identity; the peer ID is derived from the key.
- **Explicit trust**: nobody is trusted because they appear on the network. Pairing requires both
  users to approve after comparing a verification code. Revocation, impersonation warnings and
  identity-mismatch detection are built in.
- **Public rooms** (`#general` plus any you create or join), **private messages**, and
  **owner-managed private groups**.
- **Honest delivery states**: queued → sent (written to the network) → delivered (acknowledged by
  the recipient) or failed. No fake read receipts.
- **Offline queueing**: messages to a paired peer who is offline are retried when they reconnect
  (configurable, bounded, never silently deleted).
- **File transfer** with recipient approval, progress, cancellation, size limits, collision-free
  names and SHA-256 verification. Received files are never opened or executed.
- **Local history** in SQLite with search, export (JSON/text), backup and deletion.
- **Polished TUI**: responsive and compact layouts, four themes (dark, light, minimal, monochrome),
  command palette, completion, keyboard-only operation, safe rendering of untrusted text.
- **Diagnostics**: `lanchat doctor` separates socket initialisation, advertisement, discovery and
  authenticated connectivity.

## Supported platforms

| OS | Architectures | Notes |
|---|---|---|
| macOS | Apple Silicon (arm64), Intel (amd64) | allow "Local Network" access for your terminal when asked |
| Linux | amd64, arm64 | needs multicast on the LAN interface; see firewall notes |
| Windows 10/11 | amd64, arm64 | Windows Terminal or PowerShell; network profile must be *Private* |

Single static binaries without runtime dependencies (SQLite is compiled in; no CGO). What has been
verified on which platform is listed in [docs/testing.md](docs/testing.md); platform-specific
limitations are in [docs/troubleshooting.md](docs/troubleshooting.md).

## Network requirements

- Devices on the **same network segment** for automatic discovery (mDNS does not cross routers or
  VLANs). Across segments use `static_peers` or the managed discovery server.
- **UDP 5353** (mDNS) and **TCP 47777** (configurable) allowed between peers.
- No internet connection is needed or used.

Guest and hotel Wi-Fi networks often isolate clients from each other; LANChat cannot work around
that.

| Key | Action |
|---|---|
| `Enter` | send / select |
| `Alt+Enter`, `Ctrl+J` (`Shift+Enter` where the terminal reports it) | new line |
| `Tab` / `Shift+Tab` | switch panel (input, sidebar, messages) |
| `↑` / `↓` | navigate; in the input: recall previous messages |
| `PgUp` / `PgDn` | scroll the conversation |
| `Ctrl+P` | command palette |
| `Ctrl+F` | search messages |

| `Ctrl+R` | refresh discovery and retry unreachable peers |
| `F1` | help |
| `Esc` | close dialog / back to input |
| `Ctrl+C` | quit |

All bindings can be changed in the `[keys]` section of the configuration.

## Chat commands

Commands are local actions; they never execute shell commands. Start a message with `//` to send
text that begins with a slash.

| Command | Description |
|---|---|
| `/help` | commands and shortcuts |
| `/users`, `/online` | everyone known / paired peers online |
| `/rooms`, `/join <room>`, `/create <room>`, `/leave` | public rooms |
| `/msg <user> [text]` | private conversation |
| `/pair <user>`, `/unpair <user>` | verify and pair / revoke trust |
| `/group create <name> [users…]`, `/group invite\|remove <user>`, `/group members`, `/group leave` | private groups |
| `/file send <user> <path>`, `/transfers` | send files, view or cancel transfers |
| `/whoami`, `/status`, `/network`, `/ping [user]` | identity, status, network details, round-trip time |
| `/search <text>`, `/history` | search stored messages, browse conversations |
| `/clear` | clear the visible conversation (history is kept) |
| `/retry`, `/export [json\|text] [path]`, `/delete-history` | delivery and history management |
| `/theme [name]`, `/bell [on\|off]`, `/settings`, `/refresh`, `/quit` | preferences and app control |

When a name matches more than one person, LANChat asks you to choose — display names are not
identities.

## Command line

```text
lanchat [--setup] [--home DIR] [--debug]      start LANChat (wizard on first run)
lanchat --version | --help
lanchat config show|edit|validate|path
lanchat network status|interfaces|diagnose
lanchat peers list | peers revoke <peer>
lanchat identity show|fingerprint|reset
lanchat data backup <file> | export <file> [--format json|text] | purge
lanchat doctor [--verbose]
```

Exit codes: `0` ok, `1` error, `2` usage, `3` invalid configuration, `4` already running,
`5` no interactive terminal. Use `--home` (or `LANCHAT_HOME`) to run separate profiles.

## Configuration

The wizard writes `config.toml` to the platform's configuration directory
(`~/Library/Application Support/LANChat` on macOS, `$XDG_CONFIG_HOME/lanchat` on Linux,
`%APPDATA%\LANChat` on Windows). Every key is documented in
[configs/lanchat.example.toml](configs/lanchat.example.toml) and
[docs/configuration.md](docs/configuration.md). Edit with `lanchat config edit`, check with
`lanchat config validate`. Transport encryption and peer approval cannot be disabled.

## Security model

Connections are mutually authenticated TLS 1.3 sessions between Ed25519 identities; trust is
granted only by explicit pairing with a verification code bound to both keys and the TLS session;
messages are accepted only from paired peers and are attributed to the authenticated connection,
not to any claim inside the message. Messages are encrypted in transit and stored unencrypted on
your disk (protected by file permissions). Others on your network can see discovery metadata (your
display and device name, IP address and port) and that you are communicating.
Details and limitations: [SECURITY.md](SECURITY.md) and [docs/security.md](docs/security.md).

## Troubleshooting

Start with `lanchat doctor --verbose`. Common causes of "no peers": macOS Local Network permission
not granted, Windows network profile set to *Public*, a host firewall blocking UDP 5353 or TCP 47777,
Wi-Fi client isolation, or peers on different subnets. See
[docs/troubleshooting.md](docs/troubleshooting.md).

## Development

```sh
git clone https://github.com/milad-raeisi/LANChat.git
cd LANChat
make build
make test race lint vuln
```

| Target | What it does |
|---|---|
| `make build` | builds `./bin/lanchat` and `./bin/lanchat-discovery` |
| `make test`, `make race` | all tests, without / with the race detector |
| `make lint` | gofmt, go vet, staticcheck, invisible-Unicode guard |
| `make vuln` | govulncheck |
| `make bench` | benchmarks (results in [docs/performance.md](docs/performance.md)) |
| `make help` | every target |

Testing layers: unit tests per package (including fuzz tests for the protocol decoder and text
sanitizer), multi-node integration tests over real TLS sockets in `tests/integration`, CLI
end-to-end tests in `tests/e2e`, and UI tests with a fake backend in `internal/tui`.
Architecture and design decisions: [docs/architecture.md](docs/architecture.md); wire protocol:
[docs/protocol.md](docs/protocol.md).
